# HashiCorp Vault & Boundary 完整指南

> 🎯 本文件整理了 Vault 與 Boundary 的核心概念、架構設計與實作方式，適合技術團隊與 PM 閱讀。

---

## 📖 給 PM 的故事：小明的一天

### 🏢 背景

想像我們公司有一個很重要的寶庫（MongoDB 資料庫），裡面存放著客戶資料、訂單記錄等珍貴資訊。

**傳統做法的問題：**

```
以前，公司把寶庫的鑰匙（帳號密碼）寫在便條紙上，
發給每個需要進入的人。

問題來了：
❌ 小明離職了，但他記得密碼
❌ 密碼被寫在 config 檔案裡，不小心傳到 GitHub
❌ 大家都用同一組密碼，出事不知道是誰幹的
❌ 想換密碼要通知 20 個人，還要改 50 個設定檔
```

### 🔐 新方案：Vault + Boundary

現在我們引進了兩個守衛：

```
┌─────────────────────────────────────────────────────────────────────────┐
│                                                                         │
│   🏛️ Vault = 金庫管理員                                                 │
│   ─────────────────────                                                 │
│   • 負責「產生臨時鑰匙」                                                  │
│   • 每把鑰匙只能用 1 小時，時間到自動作廢                                  │
│   • 誰拿了什麼鑰匙都有記錄                                               │
│                                                                         │
│   🚪 Boundary = 大門警衛                                                 │
│   ─────────────────────                                                 │
│   • 負責「驗證身份」和「開門」                                            │
│   • 員工不需要知道寶庫在哪裡（IP 地址）                                    │
│   • 警衛會幫你把臨時鑰匙插入門鎖                                          │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 📅 小明的一天（新流程）

```
早上 9:00 - 小明要查詢客戶資料
═══════════════════════════════════════════════════════════════════════════

小明：「我要進寶庫看一下客戶資料」

     ┌──────────────┐
     │    小明      │
     │  (開發者)    │
     └──────┬───────┘
            │
            │ 1️⃣ 「我是小明，工號 A123，我要進 MongoDB」
            ▼
     ┌──────────────┐
     │   Boundary   │
     │  (大門警衛)   │──────► 確認：小明是研發部的，有權限進入
     └──────┬───────┘
            │
            │ 2️⃣ 「這位是小明，請給他一把臨時鑰匙」
            ▼
     ┌──────────────┐
     │    Vault     │
     │ (金庫管理員)  │──────► 產生臨時帳密：v-xiaoming-x7h2k9 / A1B2C3...
     └──────┬───────┘         有效期限：今天 10:00 前
            │
            │ 3️⃣ 鑰匙給警衛，警衛幫小明開門
            ▼
     ┌──────────────┐
     │   MongoDB    │
     │   (寶庫)     │
     └──────────────┘

小明順利進入，查完資料後離開。

═══════════════════════════════════════════════════════════════════════════

早上 10:01 - 臨時鑰匙自動失效
═══════════════════════════════════════════════════════════════════════════

Vault：「小明的鑰匙 v-xiaoming-x7h2k9 已過期，自動銷毀」

即使有人偷看到小明的密碼，10:01 之後這個密碼也沒用了！

═══════════════════════════════════════════════════════════════════════════

下午 3:00 - 小明離職
═══════════════════════════════════════════════════════════════════════════

HR 在系統中停用小明的帳號

之後小明再也無法通過 Boundary 的身份驗證
→ 拿不到新鑰匙
→ 進不了寶庫

✅ 不需要改任何密碼！
✅ 不需要通知任何人！
✅ 立即生效！
```

### 🤖 機器人（K8s Pod）怎麼辦？

```
機器人不需要警衛帶路，它們已經在公司內部了。

機器人的做法：
═══════════════════════════════════════════════════════════════════════════

     ┌──────────────┐
     │  K8s Pod     │
     │  (機器人)    │──────► 「我是訂單系統的機器人，這是我的工牌」
     └──────┬───────┘         (Service Account Token)
            │
            │ 直接去找金庫管理員
            ▼
     ┌──────────────┐
     │    Vault     │
     │ (金庫管理員)  │──────► 確認：這是合法的機器人，給鑰匙
     └──────┬───────┘
            │
            │ 拿著鑰匙自己去開門
            ▼
     ┌──────────────┐
     │   MongoDB    │
     └──────────────┘

機器人不需要 Boundary，因為：
• 它們已經在內網，可以直接走到寶庫門口
• 它們不是「人」，不需要互動式連線
• 它們有自己的身份證明（SA Token）
```

### 💼 對公司的好處

| 以前 | 現在 |
|------|------|
| 密碼寫在設定檔，外洩風險高 | 動態產生，用完即丟 |
| 員工離職要改密碼 | 停用帳號立即生效 |
| 不知道誰在什麼時候存取 | 完整審計日誌 |
| 密碼長期有效 | 最長 1 小時自動過期 |
| 開發者知道正式環境 IP | 開發者只知道 localhost |

## 🔧 技術細節

### 核心元件

| 元件 | 角色 | 說明 |
|------|------|------|
| **Vault** | Secrets 管理 | 動態產生資料庫憑證，管理 TTL 和撤銷 |
| **Boundary Controller** | 控制平面 | 身份驗證、授權、Session 管理 |
| **Boundary Worker** | 資料平面 | 代理連線，憑證注入 |
| **Target** | 目標資源 | 一個 DB Instance 對應一個 Target |
| **Session** | 連線會話 | 每次 connect 產生一個新 Session |

### 整體架構圖

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│                              整體安全存取架構                                     │
└─────────────────────────────────────────────────────────────────────────────────┘

                                    ┌──────────────┐
                                    │    使用者     │

                                           │

│  ┌─────────────────────────────────────────────────────────────────────────────┐ │
│  │  • 身份驗證 (OIDC / LDAP / Password)                                        │ │
│  │  • 授權檢查 (RBAC - 基於角色的存取控制)                                      │ │
│  │  • Session 建立與管理                                                       │ │
│  └─────────────────────────────────────────────────────────────────────────────┘ │
```

## 👤 人員連線方式

### 使用 CLI 連線

```bash
# 啟動 Boundary 代理
$ boundary connect mongodb -target-id ttcp_1234567890

# 輸出
Session ID: s_abc123
Proxy listening on: localhost:54321
Credentials:
  Username: v-ldap-readonly-x7h2k9
  Password: A1B2C3D4-E5F6-G7H8

# 使用 mongosh 連線
$ mongosh mongodb://localhost:54321/mydb
```

### 使用 MongoDB Compass 連線

1. 開啟終端機，啟動 Boundary 代理：
   ```bash
   boundary connect -target-id ttcp_1234567890 -listen-port 27018
   ```

2. 複製輸出的帳密資訊

3. 在 MongoDB Compass 貼上連線字串：
   ```
   mongodb://v-boundary-readonly-x7h2k9:A1B2C3D4@localhost:27018/?authSource=admin
   ```

4. 點擊 Connect

> ⚠️ **注意**：終端機視窗要保持開啟，關掉就斷線了

## 🤖 K8s Pod 連線方式

K8s Pod 直接使用 Vault，不需要 Boundary。

### 架構圖

```
                                K8s Cluster
    ┌─────────────────────────────────────────────────────────────────────────────┐
    │                                                                             │
    │   ┌─────────────────────────────────────────────────────────────────────┐   │
    │   │                           Pod                                       │   │
    │   │   ┌─────────────────────────────────────────────────────────────┐   │   │
    │   │   │  Service Account Token (自動掛載)                            │   │   │
    │   │   │  /var/run/secrets/kubernetes.io/serviceaccount/token        │   │   │
    │   │   └─────────────────────────────────────────────────────────────┘   │   │
    │   │                              │                                      │   │
    │   │                              │ 1️⃣ 用 SA Token 向 Vault 認證         │   │
    │   │                              ▼                                      │   │
    │   └──────────────────────────────┼──────────────────────────────────────┘   │
    │                                  │                                          │
    └──────────────────────────────────┼──────────────────────────────────────────┘
                                       │
                                       ▼
    ┌─────────────────────────────────────────────────────────────────────────────┐
    │                              Vault                                          │
    │   ┌─────────────────────────────────────────────────────────────────────┐   │
    │   │                    Kubernetes Auth Method                           │   │
    │   │   驗證 SA Token → 產生 Vault Token → 取得 MongoDB 憑證              │   │
    │   └─────────────────────────────────────────────────────────────────────┘   │
    └─────────────────────────────────────────────────────────────────────────────┘
                                       │
                                       ▼
                              ┌─────────────────┐
                              │    MongoDB      │
                              └─────────────────┘
```

### Vault 設定

```bash
# 1. 啟用 Kubernetes Auth
vault auth enable kubernetes

# 2. 設定 K8s API 連線
vault write auth/kubernetes/config \
    kubernetes_host="https://kubernetes.default.svc:443"

# 3. 建立 Role（綁定 K8s Service Account）
vault write auth/kubernetes/role/my-app \
    bound_service_account_names=my-app-sa \
    bound_service_account_namespaces=production \
    policies=mongodb-readonly \
    ttl=1h
```

### K8s 部署設定（使用 Vault Agent Sidecar）

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  template:
    metadata:
      annotations:
        vault.hashicorp.com/agent-inject: "true"
        vault.hashicorp.com/role: "my-app"
        vault.hashicorp.com/agent-inject-secret-mongo: "database/creds/mongodb-readonly"
    spec:
      serviceAccountName: my-app-sa
      containers:
      - name: app
        image: my-app:latest
        # 憑證會自動出現在 /vault/secrets/mongo
```

## 📊 人 vs 機器 認證比較

| 面向 | 👤 人（開發者） | 🤖 機器（K8s Pod） |
|------|----------------|-------------------|
| **認證方式** | OIDC / LDAP / Password | K8s Service Account Token |
| **需要 Boundary?** | ✅ 是（互動式連線） | ❌ 否（直接連 Vault） |
| **憑證取得** | 手動 `boundary connect` | 自動（Pod 啟動時） |
| **憑證注入** | Boundary 代理注入 | Vault Agent / App 自己拿 |
| **連線方式** | localhost:port 代理 | 直連 MongoDB IP |

## 🏗️ Worker 架構說明

一個 Worker 可以處理多個連線和多個 Target：

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│                            Boundary Worker (資料平面)                            │
│                                                                                 │
│   一個 Worker 可以同時處理：                                                     │
│                                                                                 │
│   Session 1 ─────────────────────────────────► MongoDB (生產)                   │
│   Session 2 ─────────────────────────────────► MongoDB (測試)                   │
│   Session 3 ─────────────────────────────────► PostgreSQL                       │
│   Session 4 ─────────────────────────────────► SSH Server                       │
│      ...                                                                        │
│                                                                                 │
└─────────────────────────────────────────────────────────────────────────────────┘
```

### 什麼時候需要多個 Worker？

- **不同網路區域**：DMZ、內網 A、內網 B 各部署一個
- **高可用 (HA)**：多個 Worker 做負載平衡
- **跨雲環境**：AWS、GCP、Azure 各部署一個

## 📝 術語表

| 術語 | 說明 |
|------|------|
| **Vault** | HashiCorp 的密鑰管理工具 |
| **Boundary** | HashiCorp 的安全遠端存取工具 |
| **Target** | Boundary 中代表一個被存取的資源（如 DB） |
| **Session** | 一次連線會話 |
| **Dynamic Secrets** | 動態產生的短期憑證 |
| **TTL** | Time To Live，憑證有效期限 |
| **Credential Brokering** | Boundary 向 Vault 請求憑證並注入連線 |
| **Service Account (SA)** | K8s 中給 Pod 使用的身份帳號 |
